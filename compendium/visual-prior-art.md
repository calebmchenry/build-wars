# Visual Prior Art

This note is the canonical prior-art inventory and visual reference brief for
EPIC-07. It is a development-reference layer for EPIC-08 and later UI work, not
a runtime media approval record and not a pixel-perfect implementation spec.

Screenshots remain covered by [Source policy](source-policy.md): they may be
linked from planning notes as local development evidence, but they must not be
embedded as images, copied into runtime paths, transformed, redistributed, or
treated as approved public-release assets without a future explicit ticket and
review.

## Interpretation Rules

- Use exact repository-relative screenshot paths when citing evidence.
- Treat screenshot dimensions as inventory metadata only. They are not layout
  widths, breakpoints, spacing tokens, or acceptance thresholds.
- Separate visible facts from implementation decisions. Static screenshots do
  not prove keyboard focus, animation timing, hover delay, responsive behavior,
  loading states, validation copy, or accessibility behavior.
- Use the taxonomy below for inventory grouping. A screenshot can have multiple
  categories, but it appears only once in the inventory.
- Keep PvX and community references structural. Do not copy guide prose,
  ratings, recommendations, usage notes, or build content into runtime data or
  public-facing docs from this note.

## Evidence-Derived Visual Characteristics

The following guidance is non-binding. It summarizes recurring evidence for
future design work while keeping final product decisions with the implementing
epics.

- Dense tool surfaces: panel, menu, dialog, and tooltip evidence repeatedly use
  compact spacing and high information density. Supported by VP-OBS-001,
  VP-OBS-006, VP-OBS-012, and VP-OBS-015. Limitation: density must be balanced
  with accessibility and modern input targets.
- Framed dark overlays: in-game editor surfaces lean on dark translucent panels,
  metallic or light borders, and beveled controls. Supported by VP-OBS-001,
  VP-OBS-009, VP-OBS-011, and VP-OBS-016. Limitation: exact border geometry and
  transparency are not requirements.
- Warm headings and cool controls: headings often sit in warm gold/off-white
  families, while selected controls and buttons use cool blue or green accents.
  Supported by VP-OBS-002, VP-OBS-003, VP-OBS-009, and VP-OBS-010. Limitation:
  implementation must select accessible color tokens rather than sampling
  screenshots.
- Icon-first scanning: skills, menus, template actions, sort choices, party
  members, and equipment slots rely heavily on icons adjacent to short labels or
  values. Supported by VP-OBS-005, VP-OBS-008, VP-OBS-011, VP-OBS-015,
  VP-OBS-019, and VP-OBS-022. Limitation: prior-art icons are not runtime assets.
- Focused composer baseline: SPRINT-019 applies the skill/attribute panel and
  PvX display evidence as a two-panel authoring surface with local placeholder
  icons and product-owned resource glyphs only. Remote media IDs remain
  metadata-only until a future exact approved asset ticket identifies local
  files and provenance.
- Stable alignment: skill rows consistently reserve aligned areas for icons,
  names, and cost/value facts. Supported by VP-OBS-006, VP-OBS-007, and
  VP-OBS-017. Limitation: EPIC-08 still owns responsive and overflow behavior.
- Party slot summaries: SPRINT-018 applies the party-selector evidence as
  compact ordered cards with visible selected, empty, occupied, dormant, and
  unassigned states. It uses local CSS placeholders and text summaries only;
  portrait assets, hero identity art, and full party-window matching remain
  out of runtime scope.
- Layered hover help: skill rows, skill bar slots, attribute rows, template
  rows, and party portraits all show adjacent overlays. Supported by VP-OBS-004,
  VP-OBS-007, VP-OBS-013, VP-OBS-016, VP-OBS-018, and VP-OBS-022. Limitation:
  static screenshots do not define timing, focus parity, or collision handling.
- Bounded deferred reuse: equipment, weapon-set, party, and PvX references are
  useful for later epics but should not expand the EPIC-08 MVP. Supported by
  VP-OBS-019 through VP-OBS-024.

- Future tickets should cite the exact screenshot path plus the relevant
  observation ID or section heading, for example `VP-OBS-005` and
  `prior-art/gw-skills-and-attributes-refs/skill-bar.png`.
- Use normal Markdown links for local planning references. Do not use Markdown
  image syntax, HTML image tags, data URLs, thumbnails, generated contact
  sheets, or runtime imports.
- If the tracked corpus changes, re-run
  `git ls-files -- 'prior-art/**/*.png' | LC_ALL=C sort`, reconcile folder
  counts, and update this note in the same change that explains the delta.
- Add taxonomy categories only with a local note explaining the new category and
  by migrating any affected inventory rows in the same change.
- Keep screenshot facts, limitations, non-binding visual guidance, and product
  UI decisions separate. Later implementation tickets may choose a different
  accessible UI treatment when product needs conflict with visual prior art.
